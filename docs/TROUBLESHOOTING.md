# 排障指南

先保留问题现场；不要删除数据目录、清空原生历史或反复恢复任务。反馈前去掉凭据和完整 token 链接。

## macOS 拦截首次打开

确认下载来自 [v0.1.4 Release](https://github.com/MingWangD/Relay/releases/tag/v0.1.4)，校验安装文件。当前版本为 ad-hoc、未公证预览版。按 [Apple 官方说明](https://support.apple.com/en-us/102445) 对单个可信 App 授权；不关闭全局保护。详见 [安装指南](INSTALLATION.md)。

## 模型目录缺失或 CLI 不可用

确认对应的 `codex`、`agy` 或 `claude` 在终端能独立启动，已登录或配置所需服务。源码开发可运行 `npm run doctor` 检查可执行文件及接口能力；它不验证账号或真实推理。

空闲时刷新模型目录。刷新失败会保留默认／已保存配置并显示原因；目录出现模型不证明账号有使用权限。CLI 版本需要支持 Relay 所用的会话控制和 Hook；只提供同名命令不足以证明兼容。

Claude 桌面目录与实际启动共享环境解析，默认从用户登录 shell 读取允许的模型、配置目录、服务地址和认证变量，设有 5 秒超时。若 shell 启动耗时、配置依赖交互或输出异常，界面会提示回退。检查 shell 配置后再刷新，不把认证值贴到 Issue。

Finder 启动采用当前 shell 快照；直接启动时显式环境优先。开发者需要保留直接启动环境时可设置 `RELAY_CLAUDE_ENV_EXPLICIT=1`。成员明确所选模型最终覆盖默认值。示例模型 `deepseek-flash` 来自实际本机配置，不是 Relay 内置模型。

## 原生终端等待确认

登录、完全访问风险声明、目录信任、系统权限和组织策略仍可能要求人工操作。打开对应终端并启用“人工接管”；检查提示内容后自行处理，再退出接管。正常阅读和滚轮不会给 CLI 发送任意键盘输入。

连接重试或终端动画不代表任务完成。超过一段时间无活动时查看诊断与成员交流；不要依据旧终端文字重复派单。

## 本地连接失败或数据目录已占用

同一数据目录只允许一个服务。先确认是否已有 Relay App／开发服务使用该目录；正常退出所属进程，再启动一个实例。不要删除活动锁或对所有 Node 进程执行终止。

App 使用随机本地端口；源码开发默认 4317。开发网页应打开服务当前输出的完整 `#token=` 链接，旧链接可能已失效。关闭浏览器不会停止开发服务的任务。

隔离测试使用独立数据目录，操作方法见 [开发指南](DEVELOPMENT.md#隔离数据与进程)。不要为了修复测试覆盖用户默认数据。

## 页面故障、接续失败或文件冲突

- 页面失去内容：使用原生“重新加载”提示或“查看 → 重新加载页面”。重载保留服务器状态，不应重建成员或重复派单。
- 服务重启／接续失败：先核对旧进程与工作区，再使用明确的成员恢复入口；不能用最近会话或隐式新建代替原身份。
- 回写冲突：保留成果与差异，处理人工修改后按提示继续；不强制覆盖用户文件。
- 导入失败：确认源服务已停止、源目标不重叠；保留原目标备份与失败证据，不重复删除／复制数据库文件。

## 反馈问题

使用 [Bug 表单](https://github.com/MingWangD/Relay/issues/new/choose)，附版本、macOS／芯片、对应 CLI 版本、最短步骤、预期与实际结果；区分夹具测试和真实模型。可以提供脱敏截图或日志片段，不上传完整本机数据库或原始终端。

凭据、认证绕过或数据泄露问题走 [私密漏洞报告](../SECURITY.md#报告漏洞)。已知限制和实际验收范围见 [VALIDATION](VALIDATION.md)。
