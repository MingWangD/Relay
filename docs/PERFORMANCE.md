# Relay 0.1.5 性能量测

2026-10-06，Apple Silicon arm64、macOS 26.4、内置 Node 24.21.0。隔离合成数据，不调用模型，不读取用户数据库。以下为一次受控量测，不能代表所有项目或真实网络／多模型压力。

## 状态更新

约 1／10／50 MiB 历史事件，两个模式各 2 次预热、12 次采样。before 使用 v0.1.4 Store；after 使用 revision 缓存。记录整个同步 mutate、各阶段、同 revision 的公开 State 读取与完整消息获取。每次更新仅改变 paused，成员／请求比较成本在此夹具中很小。

下表单位 ms，单元格为 p50 / p95。transaction 阶段包含 SQLite 全量事务及其中的 serialize，不能相加；publish 包含夹具监听器完整状态消息构建，不包含网络发送。

缓存明显减少相同 revision 的重复脱敏／序列化。50 MiB mutate p50 基本持平、p95 变慢；完整缓存使 RSS 增加。RSS 为采样最大值，不是精确进程峰值，包含顺序数据组与 GC 影响；缓存保留整份公开对象和 JSON 是明确内存代价。事件循环依旧受到全量同步更新影响。保留 SQLite 全量写入、内部克隆、请求／成员比较；未实现增量持久化或广播，不承诺大型历史不再卡顿。

消息字节数约等于历史体积，没有压缩或增量收益。夹具只度量序列化字节；真实 WebSocket 仍有现有 2 MiB 慢客户端积压保护，此记录不证明 50 MiB 网络广播持续可用。

## 快照哈希

每个独立子进程读取同一 128 MiB 文件 4 次，再串行读取 1000 个小文件。两种结果的 mode + NUL + bytes 指纹完全相同。子进程 Node 24.21.0；resourceUsage.maxRSS 在本机单位为 KiB，含 Node／模块加载，不等于纯哈希内存。

| 项目                       |            readFile 前 |             流式读取后 |
| -------------------------- | ---------------------: | ---------------------: |
| 128 MiB 文件四次耗时 ms    | 55.4, 56.7, 51.3, 52.0 | 53.4, 50.0, 49.0, 49.5 |
| 1000 小文件耗时 ms         |                  53.82 |                  70.84 |
| 进程峰值 RSS MiB           |                  321.6 |                  141.2 |
| 结束时 external memory MiB |                  130.7 |                   40.3 |

流式哈希主要降低大文件峰值内存；本轮小文件扫描更慢，不能宣称整体快照显著提速。两遍扫描、文件变化校验、符号链接目标字符串、执行权限和独立 Git 索引保持。回写及失败回滚需要完整字节的路径仍使用原方式。

复现方法见 [TESTING](TESTING.md#图片及日期目录检查)。阶段采样和生成数据留在 `.local/performance/`，不随公开源码或安装包分发。
